## 实际执行的准备步骤

### 1. 检查已有环境

```bash
pwd
ls -la
command -v brew go bun node npm gh ego-browser
go version
node --version
npm --version
xcode-select -p
sw_vers
uname -m
git status --short
```

工作目录最初只有原型文件。`git status --short` 返回 `fatal: not a git repository`；本次没有初始化 Git 仓库。

### 2. 安装 Bun

```bash
HOMEBREW_NO_AUTO_UPDATE=1 brew install bun
bun --version
```

结果为 Bun 1.4.2，安装目录 `/opt/homebrew/Cellar/bun/1.4.2`。

`HOMEBREW_NO_AUTO_UPDATE=1` 仅对当前命令生效，避免准备环境时顺带更新无关的 Homebrew 包。

### 3. 准备 Go 1.27.1

先核对 MyGo 的 `go.mod`，确认所需版本为 Go 1.27.1。通过 Go 自带的工具链下载机制验证：

```bash
GOTOOLCHAIN=go1.27.1 go version
```

输出：

```text
go version go1.27.1 darwin/arm64
```

随后升级默认 Go：

```bash
HOMEBREW_NO_AUTO_UPDATE=1 brew upgrade go
go version
```

Homebrew 将 Go 从 1.26.4 升级为 1.27.1，并清理旧版 1.26.4。默认安装目录为 `/opt/homebrew/Cellar/go/1.27.1`。首次验证下载的 Go 工具链位于 Go 的用户模块缓存中。

### 4. 创建官方 MyGo 模板

查询 CLI 发布版本，固定使用 0.1.22：

```bash
npm view mygo-cli version
bunx mygo-cli@0.1.22 init /tmp/leafmark-bootstrap
```

模板在临时目录创建，以避免初始化工具覆盖项目内的原型。初始化自动安装 MyGo Go 模块、CLI、运行时、TypeScript 和 Vite，并生成 Go 到 TypeScript 的调用代码。

随后使用下面的 Python 脚本将模板文件复制到本项目；目标已存在时会中止：

```bash
python3 - <<'PY'
from pathlib import Path
import shutil
src = Path('/tmp/leafmark-bootstrap')
dest = Path('/Users/kevinxc/Github/leafmark')
for name in ['.gitignore', 'bun.lock', 'go.mod', 'go.sum', 'index.html',
             'main.go', 'mygo.config.ts', 'package.json', 'tsconfig.json',
             'vite.config.ts', 'src', 'resources']:
    target = dest / name
    if target.exists():
        raise RuntimeError(f'目标已存在：{target}')
    if (src / name).is_dir():
        shutil.copytree(src / name, target)
    else:
        shutil.copy2(src / name, target)
PY
```

模板的模块名称配置为 `leafmark`，应用名为 `Leafmark`，应用标识为 `dev.leafmark.app`。正式开发入口位于本工作目录，临时模板不参与运行。

## 构建与产物

实际执行的双平台构建命令：

```bash
bun run build -- -platform darwin/universal,windows/amd64,windows/arm64
```

构建全部成功：

| 平台 | 产物 | 大小（构建工具报告） |
| --- | --- | --- |
| Mac Intel + Apple Silicon | `build/darwin-universal/Leafmark.app` | 31.9 MB |
| Mac 安装磁盘映像 | `build/darwin-universal/Leafmark 0.1.0.dmg` | 10.6 MB |
| Windows x64 | `build/windows-amd64/Leafmark.exe` | 16.1 MB |
| Windows x64 安装包 | `build/windows-amd64/Leafmark Setup 0.1.0.exe` | 6.7 MB |
| Windows ARM64 | `build/windows-arm64/Leafmark.exe` | 15.4 MB |
| Windows ARM64 安装包 | `build/windows-arm64/Leafmark Setup 0.1.0.exe` | 6.3 MB |

检查命令：

```bash
codesign --verify --deep --strict --verbose=2 build/darwin-universal/Leafmark.app
lipo -archs build/darwin-universal/Leafmark.app/Contents/MacOS/Leafmark
file build/windows-amd64/Leafmark.exe build/windows-arm64/Leafmark.exe
```

Mac 签名结构校验通过；通用二进制包含 `arm64 x86_64`；两个 Windows 二进制分别为 x86-64 和 Aarch64 的 PE GUI 程序。

本机可以直接启动 Mac 成品：

```bash
open build/darwin-universal/Leafmark.app
```

Mac 成品已启动。Windows 产物完成交叉编译与格式检查，尚未在 Windows 设备上运行。Windows 使用 WebView2 Runtime，目标设备需具备该运行时。

编辑器、KaTeX 和代码高亮的主脚本超过 Vite 默认 500 kB 分块建议。Mermaid 按需动态加载，并按图类型拆分。构建成功；包体积提示不代表编译失败。

Windows 安装器使用项目脚本 `scripts/build-desktop.sh`。本机 NSIS 3.13 的 solid LZMA 压缩曾报 `std::bad_alloc`，项目内 `scripts/tools/makensis` 包装器将本次安装器脚本调整为 zlib；仅修改当前构建进程的 PATH，不改系统 makensis 或 shell 配置。可直接执行：

```bash
bash scripts/build-desktop.sh -platform windows/amd64,windows/arm64
```

Windows 安装包经过 `7zz t` 完整性检查，解压后的程序与构建程序逐字节一致。
