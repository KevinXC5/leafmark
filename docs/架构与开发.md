# Leafmark 架构与开发

Leafmark 是一个桌面 Markdown 编辑器：界面使用网页技术实现，本地文件与系统操作由 Go 处理，MyGo 将两者连接成桌面应用。Bun 为开发者提供依赖安装、命令执行和前端测试能力。

## 技术分工

应用由前端界面、本地服务和桌面集成层组成，开发工具负责依赖管理、接口生成、测试与构建。

| 技术 | 负责什么 | 在 Leafmark 中的例子 |
| --- | --- | --- |
| TypeScript、HTML、CSS | 编写界面与交互；TypeScript 构建后以 JavaScript 运行 | 标签页、文件树、设置、编辑与阅读界面 |
| CodeMirror 6 | 提供文本编辑器能力，供前端扩展 | 文本输入、选区、撤销重做、语法高亮 |
| Go | 实现本地后端业务与系统操作 | 读取和保存 Markdown、管理工作区、校验图片与文件路径 |
| MyGo | 创建原生桌面窗口、承载网页界面，并连接前端与 Go 服务 | 前端调用保存接口、显示原生文件对话框；提供桌面开发与打包工具 |
| Vite | 启动前端开发服务、提供热更新，并构建前端资源 | 修改界面后即时查看效果，将源码构建成 JavaScript、CSS 等资源 |
| Bun | 安装 npm 生态的依赖、执行项目命令、运行前端测试与脚本 | `bun install`、`bun run dev`、`bun test` |

### 运行架构

前端 JavaScript 在系统 WebView 中运行。WebView 是桌面窗口内显示网页界面的组件，由 MyGo 创建和管理。前端通过 MyGo 接口调用本地 Go 服务，完成文件读写与系统操作，再根据返回结果更新界面。Go 服务运行在桌面程序中，无需部署远程服务器。

文档保存流程为：前端提交编辑内容，Go 文档服务写入磁盘并返回保存结果，前端更新标签页的保存状态。

发布时，Go 编译为本地程序，前端源码构建为随应用分发的资源。运行已打包的 Leafmark 无需安装 Bun、Go 或 TypeScript 开发工具。

### 开发工具与命令

Bun 提供包管理器、JavaScript/TypeScript 运行时和测试运行器。`bun install` 根据 `package.json` 和锁文件解析依赖，从配置的包仓库下载 npm 生态的包，并安装到 `node_modules`。依赖安装由 Bun 自身完成。

项目命令定义在 `package.json` 的 `scripts` 中。`bun run <命令名>` 执行对应命令，并将项目的 `node_modules/.bin` 加入命令搜索路径，使脚本可以直接调用 `mygo`、`vite`、`tsc` 等本地工具。

| 常用命令 | 实际工作 |
| --- | --- |
| `bun install --frozen-lockfile` | 按锁文件安装前端依赖与开发工具 |
| `bun run dev` | 调用 `mygo dev`，启动桌面开发流程，配合 Vite 热更新前端 |
| `bun run dev:web` | 调用 Vite，仅启动网页开发服务 |
| `bun run generate` | 调用 `mygo generate`，根据 Go 服务生成前端接口客户端 |
| `bun run build:web` | 调用 TypeScript 类型检查工具与 Vite，检查并构建前端 |
| `bun test` | 使用 Bun 自带的测试运行器执行前端测试 |
| `bun run check` | 依次执行 TypeScript 类型检查、Bun 前端测试和 Go 测试 |
| `bun run build:local` | 执行桌面构建脚本，协调前端构建与 MyGo 桌面打包 |

开发流程统一使用 Bun 命令入口：Bun 管理依赖与运行前端测试，TypeScript 工具检查类型，Vite 构建前端资源，Go 工具链编译本地服务，MyGo 协调桌面开发与打包。

`internal` 是 Go 的导入访问边界，其中的包只供本项目目录范围内的代码使用。`src` 是前端源码目录的命名约定，没有对应的 Go 访问规则。

前端按功能模块组织，模块专用样式与 TypeScript 文件放在同一目录，全局主题和主界面布局位于 `src/app/style.css`。编辑器原位扩展集中在 `editor/live`，编辑对话框集中在 `editor/dialogs`；编辑与阅读共用的 Markdown 语法位于 `markdown`。生成接口集中在 `platform`，第三方类型声明集中在 `types`。

`tests` 镜像源码功能目录，例如 `src/editor/live/live-table.ts` 对应 `tests/editor/live/live-table.test.ts`。应用生命周期集成测试位于 `tests/app`；性能基准与所属模块的测试放在一起，按需手动运行。新增模块及测试沿用这些目录边界。

## 调用与状态边界

前端通过 `src/platform/mygo.ts` 的 `Files`、`Workspace` 和 `Assets` 客户端调用 Go 服务。服务类型在 `internal/desktop` 中，由 `mygo.Bind` 注册；业务包不依赖 MyGo。

- 原生对话框、窗口和剪贴板操作放在桌面适配层。
- 文档保存基线和磁盘内容以 Go 文档状态为准；前端负责编辑器状态、选区、撤销历史及将草稿同步到后端。
- 读取相对图片必须使用已打开文档 ID，桌面服务从后端取得文档路径。原生选择的图片与文档相对图片使用各自的授权入口，共享图片验证逻辑。
- 工作区相对路径和近期记录的访问限制由工作区包校验，不能用前端传入的任意绝对路径代替授权。
- 新的业务逻辑优先放到已有业务包。只有需要原生窗口或系统能力的逻辑进入桌面适配层。

MyGo 会绑定服务类型的导出方法。构造函数和启动装配使用包级函数；内部辅助方法保持未导出，避免把内部操作暴露给前端。

## 核心实现

### 文档状态与文件保存

Go 文档服务维护标签、草稿、保存基线和磁盘变化摘要。前端保留每个标签的编辑器状态、选区和撤销历史，通过发送队列同步草稿。界面刷新后，根据当前进程中的文档状态恢复标签与保存基线。

关闭窗口时，桌面层暂时停止正文编辑，同步草稿并逐一检查标签；保存失败或取消保存时保留窗口和草稿。自动保存针对已有文件路径的当前文档，在停止输入两秒后执行，等待其他文件操作完成后继续调度。

文件采用 UTF-8 编码，支持中文和 emoji，保存时保留原文件的 BOM、CRLF 换行和权限。写入使用同目录临时文件和原子替换。保存前校验磁盘内容摘要，另存为禁止覆盖其他已打开标签的文件。窗口重新取得焦点或用户主动检查时检测外部变化；检测到变化后暂停自动保存，重新加载未保存文档前要求确认放弃修改。

外部修改检测不构成跨进程事务。如果其他程序在检测完成后、文件替换前写入同一文件，仍可能发生覆盖。

恢复快照在本机存储未保存内容，恢复时创建新标签并使用经过校验的 Markdown 文件名。单份上限为 1 MiB，总量上限为 5 MiB；超限或存储失败时保留旧快照并提示，延后恢复时继续保留原草稿。

### 工作区与附件

工作区扫描跳过隐藏文件、`node_modules` 和符号链接，限制为 10,000 个条目和 64 层目录。重命名禁止覆盖已有文件，已打开文件及其所在目录的重命名需先关闭相关标签。近期文件最多保留 30 条，仅授权记录中的文件路径。

已保存文档导入的图片复制到 `./assets/<文档名>/`，重名追加编号；未保存文档使用 Data URI。相对图片访问以已打开文档 ID 为入口，由 Go 根据实际文档路径解析并校验资源。

### 编辑与渲染

编辑器基于 CodeMirror 6，支持原位渲染、源码模式与独立标签状态。顶层代码块、公式和表格提供原位展示；引用或列表容器中的表格保留源码。表格修改集中提交，使一次保存对应一次撤销操作。

阅读渲染支持 CommonMark / GFM 及脚注、公式、提示块、上下标、折叠内容和 Mermaid。原始 HTML 默认按文本处理，渲染结果由 DOMPurify 净化，链接入口拒绝危险协议。Mermaid 使用严格模式，禁用交互链接、外部图片和自定义配置，限制代码规模；渲染失败时显示源码和中文提示。

HTML 导出内嵌样式、已解析的本地图片和 Mermaid SVG，远程图片保留原 URL。Markdown 导出生成副本，PDF 输出使用系统打印能力。

### 大文档处理

文档长度超过 1,000,000 个 UTF-16 代码单元时，代码块与表格回退源码显示，以减少复杂块解析开销。字数统计基于不可变文本缓存增量更新，大纲从语法树提取 ATX 和 Setext 标题。

本机测量中，16 MiB 文本首次字数统计约为 160 ms，缓存后的局部编辑统计约为 0.02 ms。这些数据仅覆盖字数统计，不包含完整编辑器处理与草稿同步开销。

## 本地开发

需要 Go 1.27.1+ 与 Bun 1.4.2+。

```bash
bun install --frozen-lockfile
bun run dev
```

仅启动网页界面：

```bash
bun run dev:web
```

网页开发服务用于界面与前端交互验证；真实本地文件和系统能力通过桌面程序验证。

## 接口生成

修改 Go 服务的导出方法、参数或返回类型后运行：

```bash
bun run generate
bun run typecheck
```

绑定输出路径由 `mygo.config.ts` 的 `bindings` 指定为 `src/platform/mygo.ts`。生成文件不手工修改。迁移 Go 服务时核对生成结果，保持前端契约一致。

## 自动验证

日常完成一轮改动后：

```bash
bun run check
```

开发过程中可按改动范围运行 `bun test tests/file-browser/file-browser.test.ts` 或 `go test ./internal/documents`；涉及并发、锁或文件生命周期时对相关包运行 `go test -race`。发布前运行 `bun run check:release`，检查竞态、静态分析和验证构建标签。

前端测试覆盖编辑、渲染、表格、会话、恢复、设置与导航；Go 测试覆盖文档状态、编码、文件操作、授权路径与图片处理。完整流程见根目录 [AGENTS.md](../AGENTS.md)。

原生验证：

```bash
bun run verify:native
```

该命令构建无需压缩的验证前端，并使用 `go run -tags verification .` 启动根包。界面与本地文件功能优先通过原生验证，不重复运行相同覆盖的浏览器全量场景。`internal/desktop/verification_enabled.go` 在验证构建中准备独立数据、执行 WKWebView 场景并自动退出；普通构建使用 `verification_disabled.go` 的空实现。输出写入 `verification/`，不纳入版本库。

验证构建标签也可单独检查：

```bash
go test -tags verification ./internal/desktop
```

### 验证覆盖与验收边界

| 验证方式 | 覆盖范围 |
| --- | --- |
| 前端单元与行为测试 | 格式操作、渲染安全、表格、设置、快捷键、文件导航、标签选区与撤销历史隔离、草稿发送顺序、自动保存等待和恢复快照 |
| Go 测试 | 文件操作、路径授权、图片处理、文本编码、文档状态与并发 |
| macOS WKWebView 原生自动化 | 中文与 emoji 内容、撤销重做、磁盘保存与重新读取、多标签草稿、取消关闭、两秒自动保存、工作区、相对图片、外部变化检测和重新加载 |
| 浏览器交互验证 | 浮动工具栏的显示与点击等界面交互；脚本位于 `scripts/verify-browser.mjs` |

原生后台 WebView 自动化未覆盖浮动工具栏取得焦点后的显示与点击。Windows 已完成交叉编译与安装包生成，尚未实机验证。拼音候选词、组合输入、Windows 输入法、系统打印和完整原生文件选择框交互需人工验收。

## GitHub 发布与签名更新

`package.json` 的 `version` 是版本号唯一来源，`mygo.config.ts` 读取它并配置 `KevinXC5/leafmark` 为更新源。MyGo 构建把版本、平台更新清单地址与 Ed25519 公钥注入应用。`internal/desktop/updates.go` 封装检查和安装，通过互斥锁阻止重复检查与安装；网络检查限时三十秒，安装限时十五分钟。后台检查失败保持安静，手动操作显示错误。

`.github/workflows/release.yml` 在推送 `vX.Y.Z` 标签时发布，也支持手动重试已有标签。流程核对标签与应用版本、确认提交属于 `main`，执行发布检查，在 macOS 分别构建 arm64 和 amd64 DMG，在 Ubuntu 构建 Windows amd64 和 arm64 安装程序。安装包文件名包含平台和架构，避免发布资产同名冲突。所有平台上传完成、更新清单与包大小核对通过后，生成 SHA-256 清单并发布草稿。已公开的同版本不会再次覆盖。

更新私钥保存在仓库的 `MYGO_UPDATER_PRIVATE_KEY` Actions Secret 中，公钥随源码分发。私钥必须长期保管，不能写入版本库或日志；更换公钥需要考虑旧版应用无法信任新密钥的问题。本地更新密钥文件放在仓库外，发布构建通过同名环境变量读取私钥。

应用读取最新 Release 的平台更新清单，仅安装更高版本。下载、Ed25519 签名验证、解包和跨平台替换由 MyGo 完成；安装后下次启动生效，不强制重启或关闭未保存文档。`update-*.json` 与对应 `.tar.gz` 必须一同发布。开发构建与不可写的安装位置不启用更新。操作系统代码签名与更新签名各自独立，Apple 公证和 Windows Authenticode 需另行配置证书。

发布新版本时更新 `package.json`，提交后推送同版本标签，例如：

```bash
git tag v0.1.0
git push origin main v0.1.0
```

## 构建与预览

本机应用构建只生成当前系统与架构，跳过 DMG 和公证：

```bash
bun run build:local
```

发布或导出预览时：

```bash
bun run build -- -platform darwin/universal,windows/amd64,windows/arm64
bun run preview:export
```

桌面构建已包含前端构建与类型检查，无需紧接着重复执行 `build:web`。日常前端修改使用 `bun run dev` 的热更新查看效果。

桌面产物位于 `build/`；离线预览为根目录的 `Leafmark-preview.html`。预览是生成产物，不纳入版本库。

前端入口为 `src/main.ts`，同时被 `index.html` 和 `scripts/bundle-preview.ts` 引用，由入口加载 `src/app/bootstrap.ts`。浏览器验证脚本直接访问 `src/documents/session-recovery.ts`；移动这些模块时需同步相关引用。
