# Leafmark 架构与开发

Leafmark 是一个桌面 Markdown 编辑器：界面使用网页技术实现，本地文件与系统操作由 Go 处理，MyGo 将两者连接成桌面应用。Bun 为开发者提供依赖安装、命令执行和前端测试能力。设计源文件为 `Leafmark.pen`。

## 技术分工

这些技术分别负责应用界面、本地能力、桌面集成和开发工具，职责如下：

| 技术 | 负责什么 | 在 Leafmark 中的例子 |
| --- | --- | --- |
| TypeScript、HTML、CSS | 编写界面与交互；TypeScript 构建后以 JavaScript 运行 | 标签页、文件树、设置、编辑与阅读界面 |
| CodeMirror 6 | 提供文本编辑器能力，供前端扩展 | 文本输入、选区、撤销重做、语法高亮 |
| Go | 实现本地后端业务与系统操作 | 读取和保存 Markdown、管理工作区、校验图片与文件路径 |
| MyGo | 创建原生桌面窗口、承载网页界面，并连接前端与 Go 服务 | 前端调用保存接口、显示原生文件对话框；提供桌面开发与打包工具 |
| Vite | 启动前端开发服务、提供热更新，并构建前端资源 | 修改界面后即时查看效果，将源码构建成 JavaScript、CSS 等资源 |
| Bun | 安装 npm 生态的依赖、执行项目命令、运行前端测试与脚本 | `bun install`、`bun run dev`、`bun test` |

### 应用运行时如何协作

用户操作界面时，前端 JavaScript 在 MyGo 承载的系统 WebView 中运行。WebView 可以理解为桌面窗口内用于显示网页的浏览器组件。需要读写本地文件时，前端通过 MyGo 提供的接口调用 Go 服务，再将结果显示在界面上。

例如，用户点击“保存”后，前端将编辑内容交给 Go 文档服务，由 Go 写入磁盘并返回保存结果，前端据此更新标签页状态。这里的“后端”指桌面程序中的本地 Go 服务，无需部署远程服务器。

打包后，Go 编译为本地程序，前端源码构建为随应用分发的资源。用户安装并运行 Leafmark 时，无需安装 Bun、Go 或 TypeScript 开发工具。

### Bun 在开发流程中的作用

Bun 自带包管理器。`bun install` 会读取 `package.json` 和锁文件，从配置的包仓库下载依赖并安装到 `node_modules`，不会在底层调用 `npm install`。“npm 包”指 npm 生态中发布的包，安装这些包可以使用 Bun、npm 等不同工具。

项目的常用命令定义在 `package.json` 的 `scripts` 中，`bun run <命令名>` 负责读取并执行对应命令，也会让命令能找到项目安装的 `mygo`、`vite`、`tsc` 等工具。具体工作仍由各工具完成：

| 常用命令 | 实际工作 |
| --- | --- |
| `bun install --frozen-lockfile` | 按锁文件安装前端依赖与开发工具 |
| `bun run dev` | 调用 `mygo dev`，启动桌面开发流程，配合 Vite 热更新前端 |
| `bun run dev:web` | 调用 Vite，仅启动网页开发服务 |
| `bun run generate` | 调用 `mygo generate`，根据 Go 服务生成前端接口客户端 |
| `bun run build:web` | 调用 TypeScript 类型检查工具与 Vite，检查并构建前端 |
| `bun test` | 使用 Bun 自带的测试运行器执行前端测试 |
| `bun run check` | 依次执行 TypeScript 类型检查、Bun 前端测试和 Go 测试 |
| `bun run build:local` | 执行桌面构建脚本，协调前端构建与 MyGo 桌面打包 |

Makefile 也可以统一执行这些命令，但依赖安装、前端测试和构建仍需相应工具。Leafmark 已使用 Bun 安装依赖与运行测试，因此同时用它作为常用命令入口，减少开发环境所需的额外工具。Go 编译由 Go 工具链完成，前端资源构建由 Vite 完成。

## 目录与职责

| 位置 | 职责 |
| --- | --- |
| `main.go` | 调用 `desktop.Run()` 启动程序 |
| `internal/desktop/app.go` | 装配服务、注册 MyGo 绑定、创建主窗口 |
| `internal/desktop/lifecycle.go` | 关闭前同步草稿、检查所有标签、询问保存并处理取消 |
| `internal/desktop/files.go` | 文档接口、打开与保存对话框、Markdown 副本导出 |
| `internal/desktop/workspace.go` | 工作区接口、目录选择、HTML 导出与文件定位 |
| `internal/desktop/assets.go` | 根据已打开文档 ID 授权资源访问、选择导入图片 |
| `internal/desktop/system.go` | 外部链接校验、剪贴板与系统打印 |
| `internal/documents/` | 文档与标签状态、草稿、编码、保存基线、磁盘变化检测 |
| `internal/workspace/` | 工作区状态、目录树、文件操作、授权路径与近期记录 |
| `internal/assets/` | 图片格式与大小校验、解码、Data URI、附件导入 |
| `src/main.ts` | 装配编辑器与界面、连接服务、注册用户操作 |
| `src/app-template.ts` | 主界面的静态页面模板 |
| `src/document-session.ts` | 标签编辑状态、保存基线、草稿发送队列、自动保存与关闭同步 |
| `src/session-recovery.ts` | 本机恢复快照的序列化、校验与容量限制 |
| `src/` 其他模块 | 编辑器扩展、阅读渲染、设置与交互 |
| `src/mygo.ts` | 自动生成的接口客户端与传输类型 |
| `tests/` | 前端行为与状态测试 |
| `scripts/` | 桌面构建、离线预览和浏览器验证 |

`internal` 是 Go 的导入访问边界，其中的包只供本项目目录范围内的代码使用。`src` 是前端源码目录的命名约定，没有对应的 Go 访问规则。

## 调用与状态边界

前端通过 `src/mygo.ts` 的 `Files`、`Workspace` 和 `Assets` 客户端调用 Go 服务。服务类型在 `internal/desktop` 中，由 `mygo.Bind` 注册；业务包不依赖 MyGo。

- 原生对话框、窗口和剪贴板操作放在桌面适配层。
- 文档保存基线和磁盘内容以 Go 文档状态为准；前端负责编辑器状态、选区、撤销历史及将草稿同步到后端。
- 读取相对图片必须使用已打开文档 ID，桌面服务从后端取得文档路径。原生选择的图片与文档相对图片使用各自的授权入口，共享图片验证逻辑。
- 工作区相对路径和近期记录的访问限制由工作区包校验，不能用前端传入的任意绝对路径代替授权。
- 新的业务逻辑优先放到已有业务包。只有需要原生窗口或系统能力的逻辑进入桌面适配层。

MyGo 会绑定服务类型的导出方法。构造函数和启动装配使用包级函数；内部辅助方法保持未导出，避免把内部操作暴露给前端。

## 本地开发

需要 Go 1.27.1+ 与 Bun 1.4.2+。

```bash
bun install --frozen-lockfile
bun run dev
```

仅启动网页界面：

```bash
bun run dev:web
```

网页开发服务用于界面与前端交互验证；真实本地文件和系统能力通过桌面程序验证。

## 接口生成

修改 Go 服务的导出方法、参数或返回类型后运行：

```bash
bun run generate
bun run typecheck
```

绑定输出路径由 `mygo.config.ts` 的 `bindings` 指定为 `src/mygo.ts`。生成文件不手工修改。迁移 Go 服务时核对生成结果，保持前端契约一致。

## 自动验证

日常完成一轮改动后：

```bash
bun run check
```

开发过程中可按改动范围运行 `bun test tests/file-browser.test.ts` 或 `go test ./internal/documents`；涉及并发、锁或文件生命周期时对相关包运行 `go test -race`。发布前运行 `bun run check:release`，检查竞态、静态分析和验证构建标签。

前端测试覆盖编辑、渲染、表格、会话、恢复、设置与导航；Go 测试覆盖文档状态、编码、文件操作、授权路径与图片处理。完整流程见根目录 [AGENTS.md](../AGENTS.md)。

原生验证：

```bash
bun run verify:native
```

该命令构建无需压缩的验证前端，并使用 `go run -tags verification .` 启动根包。界面与本地文件功能优先通过原生验证，不重复运行相同覆盖的浏览器全量场景。`internal/desktop/verification_enabled.go` 在验证构建中准备独立数据、执行 WKWebView 场景并自动退出；普通构建使用 `verification_disabled.go` 的空实现。输出写入 `verification/`，不纳入版本库。

验证构建标签也可单独检查：

```bash
go test -tags verification ./internal/desktop
```

具体功能和人工验收边界见[功能与使用](功能实现与使用.md)。

## 构建与预览

本机应用构建只生成当前系统与架构，跳过 DMG 和公证：

```bash
bun run build:local
```

发布或导出预览时：

```bash
bun run build -- -platform darwin/universal,windows/amd64,windows/arm64
bun run preview:export
```

桌面构建已包含前端构建与类型检查，无需紧接着重复执行 `build:web`。日常前端修改使用 `bun run dev` 的热更新查看效果。

桌面产物位于 `build/`；离线预览为根目录的 `Leafmark-preview.html`。预览是生成产物，不纳入版本库。

前端入口为 `src/main.ts`，同时被 `index.html` 和 `scripts/bundle-preview.ts` 引用。浏览器验证脚本直接访问 `src/session-recovery.ts`；移动这些模块时需同步相关引用。
